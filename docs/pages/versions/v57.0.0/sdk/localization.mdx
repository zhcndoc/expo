`expo-localization` 允许你本地化你的应用，为特定地区、语言或文化定制体验。它还提供对原生设备上区域设置数据的访问。将 [`lingui-js`](https://lingui.dev/introduction)、[`react-i18next`](https://react.i18next.com/)、[`react-intl`](https://formatjs.io/docs/getting-started/installation/)、[`i18n-js`](https://github.com/fnando/i18n-js) 或 [`react-native-intlayer`](https://intlayer.org/doc/environment/react-native-and-expo) 等本地化库与 `expo-localization` 一起使用，将使你能够为用户创建非常易于访问的体验。

## 应用配置中的配置

如果你在项目中使用配置插件（[Continuous Native Generation (CNG)](/workflow/continuous-native-generation/)），则可以使用 `expo-localization` 内置的 [config plugin](/config-plugins/introduction/) 进行配置。该插件允许你配置运行时无法设置的各种属性，并且这些更改需要构建新的应用二进制文件后才会生效。如果你的应用**不**使用 CNG，那么你需要手动配置该库。

<ConfigPluginExample>

```json app.json
{
  "expo": {
    "plugins": ["expo-localization"]
  }
}
```

## API

```jsx
import { getLocales, getCalendars } from 'expo-localization';
```

### 行为

您可以使用同步的 `getLocales()` 和 `getCalendars()` 方法来获取用户设备的区域设置。在 iOS 上，只要应用在运行，结果就会保持不变。

在 Android 上，用户可以在“设置”中更改区域偏好，而无需重启应用。为了保持本地化设置的最新状态，您可以在应用每次回到前台时重新运行 `getLocales()` 和 `getCalendars()` 方法。使用 `AppState` 来检测这一点。
