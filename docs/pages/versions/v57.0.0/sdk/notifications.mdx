`expo-notifications` 提供了一个 API，用于获取推送通知令牌，以及展示、安排、接收和响应通知。

> **warning** `expo-notifications` 提供的推送通知（远程通知）功能在 SDK 53 起的 Android 版 Expo Go 中不可用。要使用推送通知，需要一个 [开发构建](/develop/development-builds/introduction/)。本地通知（应用内通知）在 Expo Go 中仍然可用。

## 功能

- 为特定日期或从现在起的某个时间安排一次性通知
- 安排按某个时间间隔重复的通知（或在 iOS 上按日历日期匹配）
- 获取并设置应用角标图标数字
- 获取原生设备推送令牌，以便你可以使用 FCM（适用于 Android）和 APNs（适用于 iOS）发送推送通知
- 获取 Expo 推送令牌，以便你可以使用 [Expo Push Service](/push-notifications/sending-notifications/) 发送推送通知
- 监听前台和后台传入的通知
- 监听与通知的交互
- 在应用处于前台时处理通知
- 以命令式方式从通知中心/托盘中清除通知
- 创建、更新和删除 [Android 通知渠道](https://developer.android.com/develop/ui/views/notifications/channels)
- 为 Android 上的通知设置自定义图标和颜色。

### 已知问题 <PlatformTags platforms={['android']} />

在 **Android 开发构建** 中从推送通知启动应用时，启动画面大约有 70% 的概率无法正确显示。图标和淡入动画可能不会按预期出现。

- 图标可能缺失
- 淡入动画可能不会运行
- 可能只会短暂闪现背景色

此问题仅影响调试构建，不会在正式构建中出现。作为临时解决方案，请在发布模式下测试通知启动（`npx expo run:android --variant release`），以获得准确的行为表现。

## 用法

查看下面的示例 Snack，了解 Notifications 的实际效果。推送通知可在真机、启用了 Google Play services 的 Android 模拟器，以及 Xcode 14 或更高版本（macOS 13+、iOS 16+）上的 iOS 模拟器中使用。

<SnackInline label='推送通知' dependencies={['expo-constants', 'expo-notifications']}>

```tsx
import { useState, useEffect } from 'react';
import { Text, View, Button, Platform } from 'react-native';
import * as Notifications from 'expo-notifications';
import Constants from 'expo-constants';

Notifications.setNotificationHandler({
  handleNotification: async () => ({
    shouldPlaySound: false,
    shouldSetBadge: false,
    shouldShowBanner: true,
    shouldShowList: true,
  }),
});

export default function App() {
  const [expoPushToken, setExpoPushToken] = useState('');
  const [channels, setChannels] = useState<Notifications.NotificationChannel[]>([]);
  const [notification, setNotification] = useState<Notifications.Notification | undefined>(
    undefined
  );

  useEffect(() => {
    registerForPushNotificationsAsync().then(token => token && setExpoPushToken(token));

    if (Platform.OS === 'android') {
      Notifications.getNotificationChannelsAsync().then(value => setChannels(value ?? []));
    }
    const notificationListener = Notifications.addNotificationReceivedListener(notification => {
      setNotification(notification);
    });

    const responseListener = Notifications.addNotificationResponseReceivedListener(response => {
      console.log(response);
    });

    return () => {
      notificationListener.remove();
      responseListener.remove();
    };
  }, []);

  return (
    <View
      style={{
        flex: 1,
        alignItems: 'center',
        justifyContent: 'space-around',
      }}>
      <Text>你的 expo 推送令牌：{expoPushToken}</Text>
      <Text>{`频道：${JSON.stringify(
        channels.map(c => c.id),
        null,
        2
      )}`}</Text>
      <View style={{ alignItems: 'center', justifyContent: 'center' }}>
        <Text>标题：{notification && notification.request.content.title} </Text>
        <Text>正文：{notification && notification.request.content.body}</Text>
        <Text>数据：{notification && JSON.stringify(notification.request.content.data)}</Text>
      </View>
      <Button
        title="按下以安排通知"
        onPress={async () => {
          await schedulePushNotification();
        }}
      />
    </View>
  );
}

async function schedulePushNotification() {
  await Notifications.scheduleNotificationAsync({
    content: {
      title: "你有新邮件！📬",
      body: '这里是通知正文',
      data: { data: 'goes here', test: { test1: '更多数据' } },
    },
    trigger: {
      type: Notifications.SchedulableTriggerInputTypes.TIME_INTERVAL,
      seconds: 2,
    },
  });
}

async function registerForPushNotificationsAsync() {
  let token;

  if (Platform.OS === 'android') {
    await Notifications.setNotificationChannelAsync('myNotificationChannel', {
      name: '显示权限提示所需的频道',
      importance: Notifications.AndroidImportance.MAX,
      vibrationPattern: [0, 250, 250, 250],
      lightColor: '#FF231F7C',
    });
  }

  const { status: existingStatus } = await Notifications.getPermissionsAsync();
  let finalStatus = existingStatus;
  if (existingStatus !== 'granted') {
    const { status } = await Notifications.requestPermissionsAsync();
    finalStatus = status;
  }
  if (finalStatus !== 'granted') {
    alert('获取推送通知的推送令牌失败！');
    return;
  }
  // 了解更多关于 projectId 的信息：
  // https://docs.expo.dev/push-notifications/push-notifications-setup/#configure-projectid
  // 这里使用的是 EAS projectId。
  try {
    const projectId =
      Constants?.expoConfig?.extra?.eas?.projectId ?? Constants?.easConfig?.projectId;
    if (!projectId) {
      throw new Error('未找到项目 ID');
    }
    token = (
      await Notifications.getExpoPushTokenAsync({
        projectId,
      })
    ).data;
    console.log(token);
  } catch (e) {
    token = `${e}`;
  }

  return token;
}
```

### 使用导航处理推送通知

如果你希望在收到推送通知时深度链接到应用中的特定页面，可以配置 Expo 的任一导航系统来实现。

<Tabs>

<Tab label="Expo Router">

你可以使用 Expo Router 的[内置深度链接](/router/basics/core-concepts/#2-all-pages-have-a-url)来处理来自推送通知的传入 URL。只需配置根布局以监听传入和初始通知事件即可。

```tsx app/_layout.tsx
import { useEffect } from 'react';
import * as Notifications from 'expo-notifications';
import { router } from 'expo-router';

function useNotificationObserver() {
  useEffect(() => {
    function redirect(notification: Notifications.Notification) {
      const url = notification.request.content.data?.url;
      if (typeof url === 'string') {
        /* @info 推送该 URL。导航前你可能需要先验证格式。 */
        router.push(url);
        /* @end */
      }
    }

    /* @info 处理初始推送通知。 */
    const response = Notifications.getLastNotificationResponse();
    if (response?.notification) {
      redirect(response.notification);
    }

    /* @info 监听运行时通知。 */
    const subscription = Notifications.addNotificationResponseReceivedListener(response => {
      /* @end */
      redirect(response.notification);
    });

    return () => {
      subscription.remove();
    };
  }, []);
}

export default function Layout() {
  /* @info 在根部进行监听。确保该布局绝不会返回 **null**，否则导航将无法得到处理。 */
  useNotificationObserver();
  /* @end */

  return <Slot />;
}
```

</Tab>

<Tab label="React Navigation">

React Navigation 的手动[链接配置](https://reactnavigation.org/docs/navigation-container#linking)可用于处理来自推送通知的传入重定向：

```tsx App.tsx
import React from 'react';
import { Linking } from 'react-native';
import * as Notifications from 'expo-notifications';
import { NavigationContainer } from '@react-navigation/native';

export default function App() {
  return (
    <NavigationContainer
      linking={{
        config: {
          // 链接配置
        },
        async getInitialURL() {
          // 首先，你可能希望使用默认的深度链接处理
          // 检查应用是否通过深度链接打开
          const url = await Linking.getInitialURL();

          if (url != null) {
            return url;
          }

          // 处理来自 expo 推送通知的 URL
          const response = Notifications.getLastNotificationResponse();

          return response?.notification.request.content.data.url;
        },
        subscribe(listener) {
          const onReceiveURL = ({ url }: { url: string }) => listener(url);

          // 监听来自深度链接的传入链接
          const eventListenerSubscription = Linking.addEventListener('url', onReceiveURL);

          // 监听 expo 推送通知
          const subscription = Notifications.addNotificationResponseReceivedListener(response => {
            const url = response.notification.request.content.data.url;

            // 任意自定义逻辑，用于判断是否需要处理该 URL
            //...

            // 让 React Navigation 处理该 URL
            listener(url);
          });

          return () => {
            // 清理事件监听器
            eventListenerSubscription.remove();
            subscription.remove();
          };
        },
      }}>
      {/* 你的应用内容 */}
    </NavigationContainer>
  );
}
```

更多详情请参阅 [React Navigation 文档](https://reactnavigation.org/docs/deep-linking/#third-party-integrations)。

## 权限

### Android

- 在 Android 上，此模块需要订阅设备启动的权限。它用于在设备（重新）启动时设置计划通知。
  `RECEIVE_BOOT_COMPLETED` 权限会通过库的 **AndroidManifest.xml** 自动添加。

- 从 Android 12（API 级别 31）开始，要安排一个在精确时间触发的通知，你需要在 **AndroidManifest.xml** 中添加
  `<uses-permission android:name="android.permission.SCHEDULE_EXACT_ALARM"/>`。
  了解更多关于[精确闹钟权限](https://developer.android.com/about/versions/12/behavior-changes-12#exact-alarm-permission)的信息。

- 在 Android 13 上，应用用户必须通过操作系统自动触发的权限提示选择是否接收通知。
  在至少创建一个通知频道之前，此提示不会出现。必须先调用 `setNotificationChannelAsync`，
  再调用 `getDevicePushTokenAsync` 或 `getExpoPushTokenAsync` 以获取推送令牌。你可以在
  [官方文档](https://developer.android.com/develop/ui/views/notifications/notification-permission#new-apps)中了解更多关于 Android 13 新通知权限行为的信息。

<AndroidPermissions permissions={['RECEIVE_BOOT_COMPLETED', 'SCHEDULE_EXACT_ALARM']} />

### iOS

不需要使用说明，请参阅[与通知相关的权限](#fetch-information-about-notifications-related-permissions)。

### 解析 iOS 权限响应

在 iOS 上，发送通知的权限比 Android 更细粒度一些。这就是为什么你应该依赖 `NotificationPermissionsStatus` 的 `ios.status` 字段，而不是根级别的 `status` 字段。

此值将是以下之一，可在 `Notifications.IosAuthorizationStatus` 下访问：

- `NOT_DETERMINED`：用户尚未就应用是否允许安排通知做出选择
- `DENIED`：应用未被授权安排或接收通知
- `AUTHORIZED`：应用被授权安排或接收通知
- `PROVISIONAL`：应用被临时授权发布不打扰用户的通知
- `EPHEMERAL`：应用被授权在有限时间内安排或接收通知

## 无头（后台）通知

请参阅 [需要了解的内容](/push-notifications/what-you-need-to-know) 指南中关于无头后台通知的 [定义](/push-notifications/what-you-need-to-know/#headless-background-notifications)。

要在应用处于后台或未运行时处理通知，你需要执行以下操作：

- 将 `expo-task-manager` 包添加到你的项目中。
- [配置后台通知](#background-notification-configuration)。
- 在你的应用代码中，设置一个 [后台任务](#registertaskasynctaskname)，以便在收到通知时运行。

然后发送一条推送通知，其中：

- 仅包含 `data` 键（不包含 `title`、`body`）
- 对 iOS 设置 `_contentAvailable: true` —— 参见 [Expo 推送通知服务负载格式](/push-notifications/sending-notifications/#message-request-format)

### 后台通知配置&ensp;<PlatformTags platforms={["ios"]} />

要在 iOS 上使用无头（后台）通知推送通知，需要在应用的 **Info.plist** 文件中的 `UIBackgroundModes` 数组里包含 `remote-notification` 值。

**如果你正在使用 [CNG](/workflow/continuous-native-generation/)**，请将配置插件的 [`enableBackgroundRemoteNotifications` 属性](#configurable-properties)设为 true，预构建（prebuild）会自动应用正确的配置。

<Collapsible summary="在 iOS 上手动配置 UIBackgroundModes">

如果你没有使用连续原生生成（[CNG](/workflow/continuous-native-generation/)），或者你正在使用原生 iOS 项目，那么你需要将以下内容添加到你的 **Expo.plist** 文件中：

```xml ios/project-name/Supporting/Expo.plist
<key>UIBackgroundModes</key>
<array>
  <string>remote-notification</string>
</array>
```

### 设置自定义通知声音

要向你的应用添加自定义推送通知声音，请将 `expo-notifications` 插件添加到你的 **app.json** 文件中，然后在 `sounds` 键下提供一个本地声音文件路径数组，这些文件可用作自定义通知声音。这些本地路径相对于你的项目是本地路径。

```json app.json
{
  "expo": {
    "plugins": [
      [
        "expo-notifications",
        {
          "sounds": ["local/path/to/mySoundFile.wav"]
        }
      ]
    ]
  }
}
```

在构建你的应用后，这些文件数组将可在 [`NotificationContentInput`](#notificationcontentinput) 和 [`NotificationChannelInput`](#notificationchannelinput) 中使用。
你只需要提供基础文件名。下面是一个使用上面配置的示例：

```ts
await Notifications.setNotificationChannelAsync('new_emails', {
  name: '电子邮件通知',
  importance: Notifications.AndroidImportance.HIGH,
  sound: 'mySoundFile.wav', // 仅提供基础文件名
});

await Notifications.scheduleNotificationAsync({
  content: {
    title: "你有新邮件！📬",
    sound: 'mySoundFile.wav', // 仅提供基础文件名
  },
  trigger: {
    type: Notifications.SchedulableTriggerInputTypes.TIME_INTERVAL,
    seconds: 2,
    channelId: 'new_emails',
  },
});
```

如果你愿意，也可以手动向你的 Android 和 iOS 项目中添加通知文件：

### 管理交互式通知的通知类别

通知类别允许你创建交互式推送通知，使用户可以直接对传入的通知进行响应，
方式可以是按钮或文本回复。类别定义了用户可以执行的一组操作，然后通过在 [`NotificationContent`](#notificationcontent) 中指定 `categoryIdentifier` 将这些操作应用到通知上。

在 iOS 上，通知类别还允许你进一步自定义通知。对于每个类别，你不仅可以设置用户可执行的交互操作，还可以配置诸如当用户为你的应用禁用通知预览时显示的占位文本等内容。

## 平台特定指南

### 处理通知频道&ensp;<PlatformTags platforms={['android 8+']} />

从 Android 8.0（API 级别 26）开始，所有通知都必须分配到某个频道。对于每个频道，您可以设置应用于该频道中所有通知的视觉和听觉行为。然后，用户可以更改这些设置，并决定您应用中的哪些通知频道应该具有干扰性，或者是否完全可见，正如 [Android 开发者文档](https://developer.android.com/training/notify-user/channels) 所述。

如果您没有指定通知频道，`expo-notifications` 将为您创建一个名为 **Miscellaneous** 的备用频道。我们建议您始终为应用设置带有说明性名称的合适频道，并始终将通知发送到这些频道。

> 对于不支持此功能的平台（Android 8.0（26）以下版本和 iOS），调用这些方法不会产生任何效果。

### 自定义通知图标和颜色&ensp;<PlatformTags platforms={['android']} />

您可以通过在项目中使用 [Expo Prebuild](/workflow/continuous-native-generation) 配合 [`expo-notifications` 配置插件](#configurable-properties) 来配置通知的 `icon` 和 `color` 键。这些都是构建时设置，因此您需要使用 `eas build -p android` 或 `npx expo run:android` 重新编译原生 Android 应用，才能看到更改。

对于通知图标，请确保遵循 [Google 的设计指南](https://m2.material.io/design/iconography/product-icons.html#design-principles)
（图标必须是纯白色且背景透明），否则它可能不会按预期显示。

您还可以在 [`NotificationContentInput`](#notificationcontentinput) 中通过 `color` 属性，直接为每条通知设置自定义通知颜色。
