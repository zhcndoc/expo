`expo-notifications` 提供了用于获取推送通知令牌，以及呈现、安排、接收和响应通知的 API。

> **warning** 从 SDK 53 开始，Android 上的 Expo Go 不支持 `expo-notifications` 提供的推送通知（远程通知）功能。使用推送通知需要[开发构建](/develop/development-builds/introduction/)。本地通知（应用内通知）仍可在 Expo Go 中使用。

## 功能

- 为特定日期或从现在起的一段时间安排一次性通知
- 按某个时间间隔重复安排通知（或在 iOS 上匹配日历日期）
- 获取和设置应用角标图标的数字
- 获取原生设备推送令牌，以便使用 FCM（Android）和 APNs（iOS）发送推送通知
- 获取 Expo 推送令牌，以便通过 [Expo Push Service](/push-notifications/sending-notifications/) 发送推送通知
- 监听前台和后台收到的通知
- 监听与通知的交互
- 在应用处于前台时处理通知
- 从通知中心／通知栏中主动清除通知
- 创建、更新和删除 [Android 通知渠道](https://developer.android.com/develop/ui/views/notifications/channels)
- 在 Android 上为通知设置自定义图标和颜色

### 已知问题 <PlatformTags platforms={['android']} />

在 **Android 开发构建**中从推送通知启动应用时，启动屏幕在约 70% 的情况下可能无法正确显示。图标和淡入动画可能无法按预期显示。

- 图标可能缺失
- 淡入动画可能无法播放
- 可能只有背景颜色短暂闪烁

此问题只影响调试构建，在发布构建中不会出现。若要规避此问题，请在发布模式下测试通知启动（`npx expo run:android --variant release`），以确保行为准确。

## 用法

查看下面的示例 Snack，了解通知的实际效果。推送通知可在实体设备、装有 Google Play 服务的 Android 模拟器，以及运行 Xcode 14 或更高版本的 iOS 模拟器上使用（macOS 13+、iOS 16+）。

<SnackInline label='推送通知' dependencies={['expo-constants', 'expo-notifications']}>

```tsx
import { useState, useEffect } from 'react';
import { Text, View, Button, Platform } from 'react-native';
import * as Notifications from 'expo-notifications';
import Constants from 'expo-constants';

Notifications.setNotificationHandler({
  handleNotification: async () => ({
    shouldPlaySound: false,
    shouldSetBadge: false,
    shouldShowBanner: true,
    shouldShowList: true,
  }),
});

export default function App() {
  const [expoPushToken, setExpoPushToken] = useState('');
  const [channels, setChannels] = useState<Notifications.NotificationChannel[]>([]);
  const [notification, setNotification] = useState<Notifications.Notification | undefined>(
    undefined
  );

  useEffect(() => {
    registerForPushNotificationsAsync().then(token => token && setExpoPushToken(token));

    if (Platform.OS === 'android') {
      Notifications.getNotificationChannelsAsync().then(value => setChannels(value ?? []));
    }
    const notificationListener = Notifications.addNotificationReceivedListener(notification => {
      setNotification(notification);
    });

    const responseListener = Notifications.addNotificationResponseReceivedListener(response => {
      console.log(response);
    });

    return () => {
      notificationListener.remove();
      responseListener.remove();
    };
  }, []);

  return (
    <View
      style={{
        flex: 1,
        alignItems: 'center',
        justifyContent: 'space-around',
      }}>
      <Text>Your expo push token: {expoPushToken}</Text>
      <Text>{`Channels: ${JSON.stringify(
        channels.map(c => c.id),
        null,
        2
      )}`}</Text>
      <View style={{ alignItems: 'center', justifyContent: 'center' }}>
        <Text>Title: {notification && notification.request.content.title} </Text>
        <Text>Body: {notification && notification.request.content.body}</Text>
        <Text>Data: {notification && JSON.stringify(notification.request.content.data)}</Text>
      </View>
      <Button
        title="Press to schedule a notification"
        onPress={async () => {
          await schedulePushNotification();
        }}
      />
    </View>
  );
}

async function schedulePushNotification() {
  await Notifications.scheduleNotificationAsync({
    content: {
      title: "You've got mail! 📬",
      body: 'Here is the notification body',
      data: { data: 'goes here', test: { test1: 'more data' } },
    },
    trigger: {
      type: Notifications.SchedulableTriggerInputTypes.TIME_INTERVAL,
      seconds: 2,
    },
  });
}

async function registerForPushNotificationsAsync() {
  let token;

  if (Platform.OS === 'android') {
    await Notifications.setNotificationChannelAsync('myNotificationChannel', {
      name: 'A channel is needed for the permissions prompt to appear',
      importance: Notifications.AndroidImportance.MAX,
      vibrationPattern: [0, 250, 250, 250],
      lightColor: '#FF231F7C',
    });
  }

  const { status: existingStatus } = await Notifications.getPermissionsAsync();
  let finalStatus = existingStatus;
  if (existingStatus !== 'granted') {
    const { status } = await Notifications.requestPermissionsAsync();
    finalStatus = status;
  }
  if (finalStatus !== 'granted') {
    alert('Failed to get push token for push notification!');
    return;
  }
  // Learn more about projectId:
  // https://docs.expo.dev/push-notifications/push-notifications-setup/#configure-projectid
  // EAS projectId is used here.
  try {
    const projectId =
      Constants?.expoConfig?.extra?.eas?.projectId ?? Constants?.easConfig?.projectId;
    if (!projectId) {
      throw new Error('Project ID not found');
    }
    token = (
      await Notifications.getExpoPushTokenAsync({
        projectId,
      })
    ).data;
    console.log(token);
  } catch (e) {
    token = `${e}`;
  }

  return token;
}
```

### 使用导航处理推送通知

如果你希望在收到推送通知时深度链接到应用中的特定屏幕，可以配置 Expo 的任一导航系统来实现。

<Tabs>

<Tab label="Expo Router">

你可以使用 Expo Router 的[内置深度链接](/router/basics/core-concepts/#2-all-pages-have-a-url)来处理推送通知中的传入 URL。只需配置根布局，以监听传入通知和初始通知事件。

```tsx app/_layout.tsx
import { useEffect } from 'react';
import * as Notifications from 'expo-notifications';
import { Slot, router } from 'expo-router';

function useNotificationObserver() {
  useEffect(() => {
    function redirect(notification: Notifications.Notification) {
      const url = notification.request.content.data?.url;
      if (typeof url === 'string') {
        /* @info 推送此 URL。导航前，你可能需要验证其格式。 */
        router.push(url);
        /* @end */
        /* @info 清除已存储的响应，避免布局重新挂载时再次跳转到同一个 URL。 */
        Notifications.clearLastNotificationResponse();
        /* @end */
      }
    }

    /* @info 处理初始推送通知。 */
    const response = Notifications.getLastNotificationResponse();
    if (response?.notification) {
      redirect(response.notification);
    }

    /* @info 监听运行时通知。 */
    const subscription = Notifications.addNotificationResponseReceivedListener(response => {
      /* @end */
      redirect(response.notification);
    });

    return () => {
      subscription.remove();
    };
  }, []);
}

export default function Layout() {
  /* @info 在根布局中进行监听。确保此布局永远不会返回 **null**，否则导航将无法处理。 */
  useNotificationObserver();
  /* @end */

  return <Slot />;
}
```

</Tab>

<Tab label="React Navigation">

可以配置 React Navigation 的手动[链接配置](https://reactnavigation.org/docs/navigation-container#linking)，以处理推送通知带来的传入重定向：

```tsx App.tsx
import React from 'react';
import { Linking } from 'react-native';
import * as Notifications from 'expo-notifications';
import { NavigationContainer } from '@react-navigation/native';

export default function App() {
  return (
    <NavigationContainer
      linking={{
        config: {
          // Configuration for linking
        },
        async getInitialURL() {
          // First, you may want to do the default deep link handling
          // Check if app was opened from a deep link
          const url = await Linking.getInitialURL();

          if (url != null) {
            return url;
          }

          // Handle URL from expo push notifications
          const response = Notifications.getLastNotificationResponse();
          const notificationUrl = response?.notification.request.content.data?.url;
          if (typeof notificationUrl === 'string') {
            return notificationUrl;
          }
        },
        subscribe(listener) {
          const onReceiveURL = ({ url }: { url: string }) => listener(url);

          // Listen to incoming links from deep linking
          const eventListenerSubscription = Linking.addEventListener('url', onReceiveURL);

          // Listen to expo push notifications
          const subscription = Notifications.addNotificationResponseReceivedListener(response => {
            const url = response.notification.request.content.data?.url;

            // Any custom logic to see whether the URL needs to be handled
            //...

            if (typeof url === 'string') {
              // Let React Navigation handle the URL
              listener(url);
            }

            // Clear the stored response so the next getInitialURL call does not redirect to the same URL again
            Notifications.clearLastNotificationResponse();
          });

          return () => {
            // Clean up the event listeners
            eventListenerSubscription.remove();
            subscription.remove();
          };
        },
      }}>
      {/* Your app content */}
    </NavigationContainer>
  );
}
```

更多详情请参阅 [React Navigation 文档](https://reactnavigation.org/docs/deep-linking/#third-party-integrations)。

## 权限

### Android

- 在 Android 上，此模块需要订阅设备启动事件的权限，用于在设备重新启动时设置已安排的通知。
  该库会自动将 `RECEIVE_BOOT_COMPLETED` 权限添加到 **AndroidManifest.xml**。

- 从 Android 12（API 级别 31）开始，若要安排在精确时间触发的通知，需要在 **AndroidManifest.xml** 中添加
  `<uses-permission android:name="android.permission.SCHEDULE_EXACT_ALARM"/>`。
  详细信息请参阅[精确闹钟权限](https://developer.android.com/about/versions/12/behavior-changes-12#exact-alarm-permission)。
  `delivery: 'alarmClock'` 触发选项也需要精确闹钟权限。在 Android 13（API 级别 33）及更高版本上，闹钟、计时器和日历应用
  可以改为声明 `<uses-permission android:name="android.permission.USE_EXACT_ALARM"/>`。系统会直接授予此权限，无需用户确认。
  [Google Play 的精确闹钟政策](https://support.google.com/googleplay/android-developer/answer/13161072)将 `USE_EXACT_ALARM` 限制在这些应用类别中。

- 在 Android 13 上，应用用户必须通过操作系统自动触发的权限提示，选择是否接收通知。
  至少创建一个通知渠道后，才会显示此提示。获取推送令牌前，必须先调用 `setNotificationChannelAsync`，再调用
  `getDevicePushTokenAsync` 或 `getExpoPushTokenAsync`。关于 Android 13 新通知权限行为的更多信息，请参阅
  [官方文档](https://developer.android.com/develop/ui/views/notifications/notification-permission#new-apps)。

### 解读 iOS 权限响应

在 iOS 上，发送通知的权限比 Android 上更加细分。因此，你应该依据 `NotificationPermissionsStatus` 的 `ios.status` 字段，而不是根级别的 `status` 字段。

此值将是以下之一，可通过 `Notifications.IosAuthorizationStatus` 访问：

- `NOT_DETERMINED`：用户尚未决定是否允许应用安排通知
- `DENIED`：应用未获准安排或接收通知
- `AUTHORIZED`：应用已获准安排或接收通知
- `PROVISIONAL`：应用已获准发布非打扰式用户通知
- `EPHEMERAL`：应用已获准在有限时间内安排或接收通知

## 无头（后台）通知

请参阅[你需要了解的内容](/push-notifications/what-you-need-to-know)指南中关于无头后台通知的[定义](/push-notifications/what-you-need-to-know/#headless-background-notifications)。

若要在应用处于后台或未运行时处理通知，需要执行以下操作：

- 将 `expo-task-manager` 包添加到项目中。
- [配置后台通知](#background-notification-configuration)。
- 在应用代码中设置一个[后台任务](#registertaskasynctaskname)，以便在收到通知时运行。

然后发送满足以下条件的推送通知：

- 仅包含 `data` 键（没有 `title`、`body`）
- 对 iOS 设置 `contentAvailable: true` — 参阅 [Expo 推送通知服务负载格式](/push-notifications/sending-notifications/#message-request-format)

### 后台通知配置&ensp;<PlatformTags platforms={["ios"]} />

若要在 iOS 上使用无头（后台）推送通知，应用的 **Info.plist** 文件中的 `UIBackgroundModes` 数组必须包含 `remote-notification` 值。

**如果你正在使用 [CNG](/workflow/continuous-native-generation/)**，请将配置插件的 [`enableBackgroundRemoteNotifications` 属性](#configurable-properties)设为 true，prebuild 会自动应用正确的配置。

<Collapsible summary="在 iOS 上手动配置 UIBackgroundModes">

如果你没有使用 Continuous Native Generation（[CNG](/workflow/continuous-native-generation/)），或者使用的是原生 iOS 项目，则需要将以下内容添加到 **Expo.plist** 文件中：

```xml ios/project-name/Supporting/Expo.plist
<key>UIBackgroundModes</key>
<array>
  <string>remote-notification</string>
</array>
```

### 设置自定义通知声音

若要向应用添加自定义推送通知声音，请将 `expo-notifications` 插件添加到 **app.json** 文件中，然后在 `sounds` 键下提供可用作自定义通知声音的本地声音文件路径数组。这些路径相对于项目目录。

```json app.json
{
  "expo": {
    "plugins": [
      [
        "expo-notifications",
        {
          "sounds": ["local/path/to/mySoundFile.wav"]
        }
      ]
    ]
  }
}
```

构建应用后，这些文件即可用于 [`NotificationContentInput`](#notificationcontentinput) 和 [`NotificationChannelInput`](#notificationchannelinput)。
只需提供基础文件名。以下是使用上述配置的示例：

```ts
await Notifications.setNotificationChannelAsync('new_emails', {
  name: 'E-mail notifications',
  importance: Notifications.AndroidImportance.HIGH,
  sound: 'mySoundFile.wav', // Provide ONLY the base filename
});

await Notifications.scheduleNotificationAsync({
  content: {
    title: "You've got mail! 📬",
    sound: 'mySoundFile.wav', // Provide ONLY the base filename
  },
  trigger: {
    type: Notifications.SchedulableTriggerInputTypes.TIME_INTERVAL,
    seconds: 2,
    channelId: 'new_emails',
  },
});
```

在 iOS 上，通知类别还可以让你进一步自定义通知。对于每个类别，你可以设置用户可以执行的交互操作，并配置诸如当用户为你的应用停用通知预览时显示的占位文本等内容。

## 特定平台指南

### 处理通知渠道&ensp;<PlatformTags platforms={['android 8+']} />

从 Android 8.0（API level 26）开始，所有通知都必须分配到一个渠道。对于每个渠道，
你可以设置应用于该渠道中所有通知的视觉和听觉行为。
然后，用户可以更改这些设置，并决定你的应用中的哪些通知渠道应当具有侵扰性或完全可见，
正如 [Android developer docs](https://developer.android.com/training/notify-user/channels) 所述。

如果你未指定通知渠道，`expo-notifications` 将为你创建一个名为 **Miscellaneous** 的备用渠道。
我们建议你始终确保为应用设置合适且名称清晰的渠道，并始终将通知发送到这些渠道。

> 对于不支持此功能的平台（Android 8.0（26）以下版本和 iOS），调用这些方法不会执行任何操作

### 自定义通知图标和颜色&ensp;<PlatformTags platforms={['android']} />

你可以通过将 [`expo-notifications` config plugin](#configurable-properties) 与 [Expo Prebuild](/workflow/continuous-native-generation) 搭配使用，在项目中配置通知的 `icon` 和 `color` 键。这些是构建时设置，因此你需要使用 `eas build -p android` 或 `npx expo run:android` 重新编译原生 Android 应用，才能看到更改。

对于通知图标，请确保遵循 [Google's design guidelines](https://m2.material.io/design/iconography/product-icons.html#design-principles)
（图标必须为全白色且背景透明），否则它可能无法按预期显示。

你还可以直接在 [`NotificationContentInput`](#notificationcontentinput) 的 `color` 属性下为**每条通知**设置自定义通知颜色。
