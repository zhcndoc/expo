`expo-apple-authentication` 为 iOS 提供 Apple 认证支持。目前尚不支持 Android 或 web。

任何包含第三方认证选项的应用**必须**提供 Apple 认证作为选项，以符合 App Store Review 指南。有关更多信息，请参阅 [Sign In with Apple](https://developer.apple.com/sign-in-with-apple/) 网站上的 Apple 认证说明。

## 在应用配置中进行配置

如果项目使用配置插件（[Continuous Native Generation（CNG）](/workflow/continuous-native-generation/)），则可以使用内置的[配置插件](/config-plugins/introduction/)配置 `expo-apple-authentication`。该插件允许你配置各种无法在运行时设置、且必须构建新的应用二进制文件才能生效的属性。如果你的应用**不**使用 CNG，则需要手动配置此库。

### 设置 iOS 项目

要在应用中启用 **Sign In with Apple** 功能，请在项目的应用配置中将 [`ios.usesAppleSignIn`](../config/app/#usesapplesignin) 属性设置为 `true`：

```json app.json
{
  "expo": {
    "ios": {
      "usesAppleSignIn": true
    }
  }
}
```

<ConfigPluginExample>

在本地运行 [EAS Build](/build/introduction) 将使用 [iOS capabilities signing](/build-reference/ios-capabilities) 在构建前启用所需的功能。

```json app.json
{
  "expo": {
    "plugins": ["expo-apple-authentication"]
  }
}
```

<ConfigReactNative>

不使用 [EAS Build](/build/introduction) 的应用必须为其 bundle identifier[手动配置](/build-reference/ios-capabilities#manual-setup) **Apple Sign In** 功能。

如果你通过 [Apple Developer Console](/build-reference/ios-capabilities#apple-developer-console) 启用了 **Apple Sign In** 功能，请务必将以下 entitlements 添加到 **ios/[app]/[app].entitlements** 文件中：

```xml
<key>com.apple.developer.applesignin</key>
<array>
  <string>Default</string>
</array>
```

此外，请在 **ios/[app]/Info.plist** 中将 `CFBundleAllowMixedLocalizations` 设置为 `true`，以确保登录按钮使用设备区域设置。

</ConfigReactNative>

## 使用

<SnackInline label="Apple Authentication usage" dependencies={['expo-apple-authentication']} platforms={['ios']}>

```jsx
import * as AppleAuthentication from 'expo-apple-authentication';
import { View, StyleSheet } from 'react-native';

export default function App() {
  return (
    <View style={styles.container}>
      <AppleAuthentication.AppleAuthenticationButton
        buttonType={AppleAuthentication.AppleAuthenticationButtonType.SIGN_IN}
        buttonStyle={AppleAuthentication.AppleAuthenticationButtonStyle.BLACK}
        cornerRadius={5}
        style={styles.button}
        onPress={async () => {
          try {
            const credential = await AppleAuthentication.signInAsync({
              requestedScopes: [
                AppleAuthentication.AppleAuthenticationScope.FULL_NAME,
                AppleAuthentication.AppleAuthenticationScope.EMAIL,
              ],
            });
            // signed in
          } catch (e) {
            if (e.code === 'ERR_REQUEST_CANCELED') {
              // handle that the user canceled the sign-in flow
            } else {
              // handle other errors
            }
          }
        }}
      />
    </View>
  );
}

const styles = StyleSheet.create({
  container: {
    flex: 1,
    alignItems: 'center',
    justifyContent: 'center',
  },
  button: {
    width: 200,
    height: 44,
  },
});
```

</SnackInline>

## 开发和测试

你可以在 iOS 上的 Expo Go 中测试此库，无需遵循上述任何说明。
但是，如果你使用 EAS Build，则需要添加配置插件才能使用此库。
登录 Expo Go 时，你收到的标识符和值可能与在独立应用中收到的不同。

你可以在 iOS 模拟器中对这个库进行有限的测试。但是，并非所有方法的行为都会与在设备上一样，
因此我们强烈建议在开发过程中尽可能使用真实设备进行测试。

## 验证来自 Apple 的响应

Apple 的响应包含一个带有用户信息的已签名 JWT。为确保响应确实来自 Apple，
你可以使用 Apple 的公钥以加密方式验证签名，该公钥发布在 https://appleid.apple.com/auth/keys。
此过程并不特定于 Expo。

## 错误代码

大多数错误代码与官方的 [Apple Authorization errors](https://developer.apple.com/documentation/authenticationservices/asauthorizationerror/code) 相匹配。

| Code                        | Description                                                                         |
| --------------------------- | ----------------------------------------------------------------------------------- |
| ERR_INVALID_OPERATION       | 执行了无效的授权操作。                                                              |
| ERR_INVALID_RESPONSE        | 授权请求收到无效响应。                                                              |
| ERR_INVALID_SCOPE           | 传入了无效的 [`AppleAuthenticationScope`](#appleauthenticationscope)。              |
| ERR_REQUEST_CANCELED        | 用户取消了授权尝试。                                                                |
| ERR_REQUEST_FAILED          | 授权尝试失败。有关其他信息，请参阅错误消息。                                        |
| ERR_REQUEST_NOT_HANDLED     | 未正确处理授权请求。                                                                |
| ERR_REQUEST_NOT_INTERACTIVE | 授权请求不是交互式的。                                                              |
| ERR_REQUEST_UNKNOWN         | 授权尝试因未知原因失败。                                                            |
