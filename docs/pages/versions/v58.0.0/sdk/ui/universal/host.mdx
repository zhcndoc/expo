一个用于容纳通用 `@expo/ui` 内容的容器。在 Android 和 iOS 上，它会重新导出平台原生的 [`Host` for Jetpack Compose](../jetpack-compose/host)/[`Host` for SwiftUI](../swift-ui/host)，因此 Jetpack Compose/SwiftUI 子组件的渲染效果与平台专用包中的完全相同。在 Web 上，它会回退为 React Native [`View`](https://reactnative.dev/docs/view)。将 `Host` 用作任何通用子树的根节点，即可让同一组件树在所有三个平台上运行。

### 在 React Native 视图中放置组件

`Host` 会在 Android 上使用 Jetpack Compose、在 iOS 上使用 SwiftUI 渲染其通用子组件。`Host` 内部的 React Native 视图（例如 `View` 或 `ScrollView`）会切换回 React Native 渲染。若要在该视图中使用通用组件，请将组件包裹在新的 `Host` 中。即使视图外层的树中已有一个 `Host`，也要这样做。

<ComponentExample
  title="ReactNativeLayoutExample.tsx"
  android={{
    src: '/static/images/expo-ui/examples/universal-host-react-native-views-android-light.webp',
    darkSrc: '/static/images/expo-ui/examples/universal-host-react-native-views-android-dark.webp',
    alt: '一行标有 Notifications，尾部有一个关闭状态的 Material 3 开关',
  }}
  ios={{
    src: '/static/images/expo-ui/examples/universal-host-react-native-views-ios-light.webp',
    darkSrc: '/static/images/expo-ui/examples/universal-host-react-native-views-ios-dark.webp',
    alt: '一行标有 Notifications，尾部有一个关闭状态的开关',
  }}>

```tsx
import { useState } from 'react';
import { ScrollView, Text, View, useColorScheme } from 'react-native';
import { Host, Switch } from '@expo/ui';

export default function ReactNativeLayoutExample() {
  const colorScheme = useColorScheme();
  const [enabled, setEnabled] = useState(false);

  return (
    <ScrollView>
      <View
        style={{
          flexDirection: 'row',
          alignItems: 'center',
          justifyContent: 'space-between',
          padding: 16,
        }}>
        <Text style={{ color: colorScheme === 'dark' ? '#FFFFFF' : '#000000' }}>Notifications</Text>
        <Host matchContents>
          <Switch value={enabled} onValueChange={setEnabled} />
        </Host>
      </View>
    </ScrollView>
  );
}
```

</ComponentExample>

若要在通用布局中放置 React Native 视图，请使用 [`RNHostView`](rnhostview)。

### 匹配内容尺寸

使用 `matchContents` 让 `Host` 调整自身大小以适应其内容。在 Android 和 iOS 上，该属性会转发给平台原生的 `Host`（具体的平台语义请参阅 [Jetpack Compose](../jetpack-compose/host)/[SwiftUI](../swift-ui/host)）。在 Web 上，它会对底层 `View` 应用 `alignSelf: 'flex-start'`，使 host 收缩以适应其子组件，而不是被父组件拉伸。

> **注意：** 在 Web 上，按轴设置的形式（`{ horizontal: true }` / `{ vertical: true }`）与布尔形式的效果相同，因为 `alignSelf` 只控制在父组件交叉轴上的拉伸。依赖各轴独立调整尺寸的组件，无论选择哪个轴，都应预期 Web 上会采用相同的收缩适配行为。

<ComponentExample
  title="MatchContentsExample.tsx"
  android={{
    src: '/static/images/expo-ui/examples/universal-host-match-contents-android-light.webp',
    darkSrc: '/static/images/expo-ui/examples/universal-host-match-contents-android-dark.webp',
    alt: '尺寸适配其标签的 Material 3 按钮',

```tsx
    </Host>
  );
}
```

</ComponentExample>

### 布局方向

使用 `layoutDirection` 将子树渲染为从左到右或从右到左。在 Android 和 iOS 上，该属性会转发给平台原生的 `Host`（具体的平台语义请参阅 [Jetpack Compose](../jetpack-compose/host)/[SwiftUI](../swift-ui/host)）。在 Web 上，它会在底层 `View` 上设置 `dir` 属性，使后代继承所选方向。

<ComponentExample
  title="LayoutDirectionExample.tsx"
  android={{
    src: '/static/images/expo-ui/examples/universal-host-layout-direction-android-light.webp',
    darkSrc: '/static/images/expo-ui/examples/universal-host-layout-direction-android-dark.webp',
    alt: '两个标签按从右到左的顺序排列，Second 位于 First 之前',
  }}
  ios={{
    src: '/static/images/expo-ui/examples/universal-host-layout-direction-ios-light.webp',
    darkSrc: '/static/images/expo-ui/examples/universal-host-layout-direction-ios-dark.webp',
    alt: '两个标签按从右到左的顺序排列，Second 位于 First 之前',
  }}>

```tsx
import { useColorScheme } from 'react-native';
import { Host, Row, Text } from '@expo/ui';

export default function LayoutDirectionExample() {
  const colorScheme = useColorScheme();
  const ink = { color: colorScheme === 'dark' ? '#FFFFFF' : '#000000' };

  return (
    <Host
      layoutDirection="rightToLeft"
      matchContents={{ vertical: true }}
      style={{ width: '100%' }}>
      <Row spacing={8}>
        <Text textStyle={ink}>First</Text>
        <Text textStyle={ink}>Second</Text>
      </Row>
    </Host>
  );
}
```

</ComponentExample>

### 响应内容布局

使用 `onLayoutContent` 获取 host 内容的当前尺寸。在 Android 和 iOS 上，该属性会转发给平台原生的 `Host`（具体的平台语义请参阅 [Jetpack Compose](../jetpack-compose/host)/[SwiftUI](../swift-ui/host)）。在 Web 上，该尺寸由底层 `View` 的 `onLayout` 回调计算得出。

<ComponentExample
  title="OnLayoutContentExample.tsx"
  android={{
    src: '/static/images/expo-ui/examples/universal-host-on-layout-content-android-light.webp',
    darkSrc: '/static/images/expo-ui/examples/universal-host-on-layout-content-android-dark.webp',
    alt: '尺寸适配自身内容的 Hello world 标签',
  }}
  ios={{
    src: '/static/images/expo-ui/examples/universal-host-on-layout-content-ios-light.webp',
    darkSrc: '/static/images/expo-ui/examples/universal-host-on-layout-content-ios-dark.webp',
    alt: '尺寸适配自身内容的 Hello world 标签',
  }}>

```tsx
import { useColorScheme } from 'react-native';
import { Host, Text } from '@expo/ui';

export default function OnLayoutContentExample() {
  const colorScheme = useColorScheme();

  return (
    <Host
      matchContents
      onLayoutContent={({ nativeEvent: { width, height } }) =>
        console.log(`content size: ${width}x${height}`)
      }>
      <Text textStyle={{ color: colorScheme === 'dark' ? '#FFFFFF' : '#000000' }}>
        Hello, world!
      </Text>
    </Host>
  );
}
```

</ComponentExample>

### 填充视口

对于需要根据可用视口空间调整尺寸的内容，请使用 `useViewportSizeMeasurement`。在 Android 和 iOS 上，该属性会转发给平台原生的 `Host`（具体的平台语义请参阅 [Jetpack Compose](../jetpack-compose/host)/[SwiftUI](../swift-ui/host)）。在 Web 上，host 底层的 `View` 会被设置为当前窗口的宽度和高度；你传入的任何显式 `style` 仍具有优先级。

### 忽略安全区域

默认情况下，`Host` 会遵循设备的安全区域内边距（刘海、Home 指示条等）。使用 `ignoreSafeArea="all"` 可让内容延伸至屏幕边缘，或使用 `ignoreSafeArea="keyboard"` 保留安全区域内边距但忽略键盘内边距。在 Android 和 iOS 上，该属性会转发给平台原生的 `Host`（具体的平台语义请参阅 [Jetpack Compose](../jetpack-compose/host)/[SwiftUI](../swift-ui/host)）。在 Web 上，它通过将 CSS `env(safe-area-inset-*)` 值应用为底层 `View` 的内边距来实现；对于启用了 [VirtualKeyboard API](https://developer.mozilla.org/en-US/docs/Web/API/VirtualKeyboard_API) 的页面，默认设置还会将 `env(keyboard-inset-*)` 纳入计算。

```tsx

      </Column>
    </Host>
  );
}
```

### 强制指定配色方案

使用 `colorScheme` 覆盖子树的外观。传入 `'light'` 或 `'dark'` 可强制指定配色方案，省略则遵循设备设置。在 Android 和 iOS 上，该属性会转发给平台原生的 `Host`（具体的平台语义请参阅 [Jetpack Compose](../jetpack-compose/host)/[SwiftUI](../swift-ui/host)）。在 Web 上，它会在底层 `View` 上设置 `data-theme`，使设计令牌 CSS 变量无论 `prefers-color-scheme` 的值如何，都会解析为强制指定的配色方案。

### 设置颜色主题种子

使用 `seedColor` 从单一基色为子树派生主题。每个平台都会以原生方式处理它。在 Android 上，它会生成完整的 Material 3 调色板（`SchemeTonalSpot`，与 Material You 使用的算法相同），用于为 Compose 子组件设置主题，并通过 [`useMaterialColors`](../jetpack-compose/colors#usematerialcolorsoptions) 向后代提供。在 iOS 上，它会作为 SwiftUI tint 应用，并通过环境向下传递，为按钮、开关和滑块等交互控件设置主题。在 Web 上，它会生成一组主色阶，并以 CSS 变量的形式提供给底层 `View`。省略时，各平台会回退到其默认主题。

    alt: '一个绿色 Material 3 按钮上方有一个绿色开关',

  ios={{
