#### 已知问题&ensp;<PlatformTags platforms={['ios']} />

在 iOS 上，当从相机胶卷中选择图片（通常是[更高分辨率](https://openradar.me/49866214)的图片）时，在某些情况下，裁剪后的图像结果会给出错误的裁剪矩形值。不幸的是，这个问题出在底层的 `UIImagePickerController`，这是由于 iOS 内置的闭源工具中的一个 bug 导致的。

## 在 app 配置中进行配置

如果你在项目中使用配置插件（[Continuous Native Generation (CNG)](/workflow/continuous-native-generation/)），你可以使用 `expo-image-picker` 内置的 [config plugin](/config-plugins/introduction/) 进行配置。该插件允许你配置各种无法在运行时设置的属性，这些属性需要重新构建新的应用二进制文件后才会生效。如果你的应用**没有**使用 CNG，那么你需要手动配置该库。

默认情况下，`expo-image-picker` 会在 Android 上添加 `RECORD_AUDIO` 权限。你可以通过将下面配置中的 `microphonePermission` 设为 false 来移除它。

<ConfigPluginExample>

```json app.json
        {
          "photosPermission": "该应用访问你的照片，以便你可以与朋友分享。"
        }
      ]
    ]
  }
}
```

## 用法

<SnackInline label='Image Picker' dependencies={['expo-image-picker']}>

```tsx
import { useState } from 'react';
import { Alert, Button, Image, View, StyleSheet } from 'react-native';
import * as ImagePicker from 'expo-image-picker';

export default function ImagePickerExample() {
  const [image, setImage] = useState<string | null>(null);

  const pickImage = async () => {
    // Launching the image library requires no permissions.
    // On iOS, when `allowsEditing` is set to `false`
    // and `videoExportPreset` is `'Passthrough'` (the default), you need to request video permissions manually, preferably before opening the picker,
    // so that the system prompt doesn't interrupt users after they select a video.
    // For more details, see the "Requesting video permissions" subsection.
    const permissionResult = await ImagePicker.requestMediaLibraryPermissionsAsync();

    if (!permissionResult.granted) {
      Alert.alert('Permission required', 'Permission to access the media library is required.');
      return;
    }

    let result = await ImagePicker.launchImageLibraryAsync({
      mediaTypes: ['images', 'videos'],
      allowsEditing: true,
      aspect: [4, 3],
      quality: 1,
    });

    console.log(result);

    if (!result.canceled) {
      setImage(result.assets[0].uri);
    }
  };

  return (
    <View style={styles.container}>
      <Button title="Pick an image from camera roll" onPress={pickImage} />
      {image && <Image source={{ uri: image }} style={styles.image} />}
    </View>
  );
}

const styles = StyleSheet.create({
  container: {
    flex: 1,
    alignItems: 'center',
    justifyContent: 'center',
  },
  image: {
    width: 200,
    height: 200,
  },
});
```

</SnackInline>

### Requesting video permissions <PlatformTags platforms={['ios']} />

In SDK 54 and later, the default configuration keeps `allowsEditing` as `false` and sets [`videoExportPreset`](#videoexportpreset) to `'Passthrough'`. These settings cause the picker to skip compression and immediately return the original asset, including HEIC and AVIF files, but iOS requires media library permissions to access the original file and will display a permissions dialog right after the user selects a video.

To avoid showing a permissions dialog after selection, **manually request media library permissions** before opening the picker via [`requestMediaLibraryPermissionsAsync`](#imagepickerrequestmedialibrarypermissionsasyncwriteonly) or [`useMediaLibraryPermissions`](#usemedialibrarypermissionsoptions).
