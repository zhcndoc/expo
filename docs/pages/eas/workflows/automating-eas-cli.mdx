If you’re using EAS CLI to build, submit, and update your app, you can automate a series of commands with EAS Workflows. EAS Workflows can build, submit, and update your app, and it can also run other tasks such as Maestro tests, unit tests, custom scripts, and more.

Below, you’ll see how to set up your project to use EAS Workflows, followed by common EAS CLI command examples and how to use EAS Workflows to run them.

## 配置你的项目

EAS Workflows 可选择支持一个与你的 EAS 项目关联的 GitHub 仓库来运行。本指南假设已经关联了一个 GitHub 仓库，并展示了如何在向 GitHub 上的特定分支推送时触发工作流。你可以通过以下步骤将 GitHub 仓库关联到你的 EAS 项目：

- 前往你项目的 [GitHub 设置](https://expo.dev/accounts/%5Baccount%5D/projects/%5BprojectName%5D/github)。
- 按照界面提示安装 GitHub 应用。
- 选择与 Expo 项目匹配的 GitHub 仓库并连接它。

## 创建构建

你可以使用 EAS CLI 的 `eas build` 命令来构建你的项目。要使用 `production` 构建配置文件创建一个 iOS 构建，你可以运行以下 EAS CLI 命令：

<Terminal cmd={['$ eas build --platform ios --profile production']} />

要将此命令写成工作流，请在项目根目录下创建一个名为 **.eas/workflows/build-ios-production.yml** 的工作流文件。

在 **build-ios-production.yml** 中，你可以使用以下工作流来启动一个创建使用 `production` 构建配置文件的 iOS 构建的任务。

```yaml .eas/workflows/build-ios-production.yml
name: iOS 生产构建

on:
  push:
    branches: ['main']

jobs:
  build_ios:
    name: 构建 iOS
    type: build
    params:
      platform: ios
      profile: production
```

一旦你有了这个工作流文件，你可以通过向 `main` 分支推送提交来启动它，或者运行以下 EAS CLI 命令：

<Terminal cmd={['$ eas workflow:run .eas/workflows/build-ios-production.yml']} />

你可以提供参数来创建 Android 构建，或者使用其他构建配置文件。有关构建任务参数的更多信息，请参阅 [构建任务文档](/eas/workflows/syntax/#build)。

## 提交构建

你可以使用 EAS CLI 的 `eas submit` 命令将你的应用提交到应用商店。要提交一个 iOS 应用，你可以运行以下 EAS CLI 命令：

<Terminal cmd={['$ eas submit --platform ios']} />

要将此命令写成工作流，请在项目根目录下创建一个名为 **.eas/workflows/submit-ios.yml** 的工作流文件。

提交任务需要要提交的构建 ID。在 **submit-ios.yml** 中，你可以使用以下工作流来创建一个 iOS 构建，然后再提交它：

```yaml .eas/workflows/submit-ios.yml
name: 提交 iOS 应用

on:
  push:
    branches: ['main']

jobs:
  build_ios:
    name: 构建 iOS
    type: build
    params:
      platform: ios
      profile: production
  submit_ios:
    name: 提交 iOS
    needs: [build_ios]
    type: submit
    params:
      build_id: ${{ needs.build_ios.outputs.build_id }}
```

如果你想提交一个现有构建而不是创建新的构建，可以直接将它的 `build_id` 传给提交任务，或者使用 [`get-build`](/eas/workflows/pre-packaged-jobs/#get-build) 任务动态查找它，并传递其 `build_id` 输出。

有了这个工作流文件后，你可以通过向 `main` 分支推送提交来启动它，或者运行以下 EAS CLI 命令：

<Terminal cmd={['$ eas workflow:run .eas/workflows/submit-ios.yml']} />

你可以提供参数来使用其他提交配置文件。有关提交任务参数的更多信息，请参阅 [提交任务文档](/eas/workflows/syntax/#submit)。

## Release updates

You can use the EAS CLI `eas update` command to update your app. To update your app, you can run the following EAS CLI command:

<Terminal cmd={['$ eas update --auto']} />

To write this command as a workflow, create a workflow file named **.eas/workflows/publish-update.yml** in the project root.

In **publish-update.yml**, you can use the following workflow to start a task that sends an over-the-air update.

```yaml .eas/workflows/publish-update.yml
name: 发布更新

on:
  push:
    branches: ['*']

jobs:
  update:
    name: 更新
    type: update
    params:
      branch: ${{ github.ref_name || 'test'}}
```

Once you have this workflow file, you can trigger it by pushing a commit to any branch, or run the following EAS CLI command:

<Terminal cmd={['$ eas workflow:run .eas/workflows/publish-update.yml']} />

You can provide parameters to update a specific branch or channel, and configure the update message. For more information about update task parameters, see [更新任务文档](/eas/workflows/syntax/#update).
