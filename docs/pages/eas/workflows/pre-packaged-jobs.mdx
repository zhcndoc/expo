## Apple 设备注册请求

暂停工作流运行，直到 iOS 设备在指定的 [Apple team](https://expo.fyi/apple-team) 中注册，并且团队成员在 [expo.dev](https://expo.dev) 上批准该注册。使用此作业可以在 EAS Workflows 中自动注册用于[内部分发](/build/internal-distribution/)的设备。

当工作流到达此作业时，该作业和运行会进入 `action-required` 状态，并保持暂停，直到流程完成：

1. 工作流运行页面会显示该设备的二维码和注册链接。
2. 在 iPhone 或 iPad 上，设备会下载一个配置描述文件，并通过“设置”安装它。任一时刻只会有一个描述文件可用，如果未在八分钟内安装，它将被移除。
3. 安装后，会收集唯一设备标识符（UDID）和元数据。
4. 在工作流运行页面上，团队成员批准或拒绝该注册。批准会使作业成功，并将输出（UDID、型号等）暴露给下游作业。拒绝会使作业失败，并阻止使用 `needs` 的作业。

如果 UDID 已经在你的账户中注册，该作业在继续之前仍会等待注册和批准。

### 语法

```yaml
jobs:
  register_device:
    type: apple-device-registration-request
    params:
      apple_team_identifier: string # 可选
```

#### 参数

你可以将以下参数传入 `params` 列表：

| 参数 | 类型 | 描述 |
| --------------------- | ------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| apple_team_identifier | string | 可选。Apple Team ID（例如 `ABCDE12345`）。如果省略此参数，且你的 Expo 账户中只有一个 Apple team，则使用该团队。当你的账户中没有 Apple team 或有两个及以上 Apple team 时，必须设置此参数。提供该参数后，EAS 会根据该标识符解析或创建团队。 |

#### 输出

在团队成员批准已注册设备后，你可以在后续作业中引用以下输出：

| 输出 | 类型 | 描述 |
| ---------------- | ------ | ---------------------------------------------------------------- |
| apple_device_id  | string | Expo 内部设备 ID。                                         |
| identifier       | string | 设备 UDID。                                                     |
| name             | string | 设备名称。可能为空。                                       |
| model            | string | 硬件型号字符串（例如 `iPhone11,2`）。可能为空。 |
| device_class     | string | 设备类别：`iphone`、`ipad` 或 `mac`。可能为空。          |
| software_version | string | iOS 版本字符串。可能为空。                                |

如果团队成员拒绝该注册，作业会失败且不会设置输出。使用 `needs` 的下游作业将不会运行。

### 示例

以下是一些使用 Apple 设备注册请求作业的实际示例：

<Collapsible summary="注册设备并通知 Slack">

此工作流会注册一台 iOS 设备，并根据作业输出发送一条包含设备 UDID 和型号的 Slack 消息。

```yaml .eas/workflows/register-device-slack.yml
name: Register iOS device and notify Slack

jobs:
  register_device:
    type: apple-device-registration-request
    params:
      apple_team_identifier: XX33YYZ44Z
  notify_slack:
    needs: [register_device]
    type: slack
    environment: production
    params:
      webhook_url: ${{ env.SLACK_WEBHOOK_URL }}
      message: 'Registered device ${{ needs.register_device.outputs.identifier }} (${{ needs.register_device.outputs.model }})'
```

</Collapsible>

<Collapsible summary="注册设备，然后运行 iOS 内部构建">

此工作流会注册一台设备，然后运行一个 iOS 内部分发构建，以刷新 ad hoc 配置描述文件，从而包含新设备。

```yaml .eas/workflows/register-device-build.yml
name: Register device and build iOS internal

jobs:
  register_device:
    type: apple-device-registration-request
    params:
      apple_team_identifier: ABCDE12345
  build_ios:
    needs: [register_device]
    type: build
    params:
      platform: ios
      profile: preview
      refresh_ad_hoc_provisioning_profile: true
```

`preview` 配置文件必须设置 [`distribution: internal`](/eas/json/#distribution)，并使用[由 EAS 管理的凭证](/app-signing/app-credentials/)。对于 CI，你还需要一个 App Store Connect API 密钥。请参阅 [CI 上的内部分发](/build/internal-distribution/#automation-on-ci-optional) 和 [从 CI 触发构建](/build/building-on-ci/)。

</Collapsible>

<Collapsible summary="保存截图和录屏">

Maestro 命令（例如 [`takeScreenshot`](https://docs.maestro.dev/reference/commands-available/takescreenshot) 或 [`startRecording`](https://docs.maestro.dev/reference/commands-available/startrecording)）会保存资源，供你稍后用于调试。

在 Maestro flow 文件中，为每个资源指定一个相对路径：

```yaml maestro/flows/test-flow.yaml
appId: com.myapp
---
- launchApp
- startRecording: my_recording
- takeScreenshot: my_screenshot
- tapOn: 'Login Button'
- takeScreenshot: after_login_screenshot
- stopRecording
```

这些资源将在 Artifacts 部分中的“Maestro Test Results”产物里可用。

</Collapsible>
