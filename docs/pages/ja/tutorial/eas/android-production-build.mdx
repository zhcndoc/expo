## Android 生产构建

[Android 生产构建](/build/eas-json/#production-builds)采用针对 Google Play 商店分发进行优化的 **.aab** 格式。与 **.apk** 构建不同，**.aab** 文件只能通过 Google Play 商店进行分发和安装。

<Step label="1">

## 创建生产构建

要使用默认的 `production` 配置文件创建 Android 生产构建，请打开终端并运行以下命令。由于在 EAS 配置中 `production` 是默认配置文件，因此无需通过 `--profile` 标志明确指定。

<Terminal cmd={['$ eas build --platform android']} />

此命令会将构建加入队列。请注意，EAS 控制面板中的 **Version Code** 会自动递增。

</Step>

<Step label="2">

## 在 Google Play Console 中创建应用

> **info** 无需手动创建第一个发布版本。`eas submit` 可以直接创建应用的第一个发布版本。本教程将完整操作 Play Console，以便熟悉发布机制。

首次将应用上传到 Google Play 商店时，请按照以下步骤操作。

- 前往 Google Play 控制面板。
- 在 **首页** 页面中，点击 **创建应用** 以创建新应用。

<ContentSpotlight

  className="max-w-[800px]"
/>

- 输入应用详细信息，然后点击 **创建应用** 按钮。

<ContentSpotlight
  alt="Google Play Console 中的创建应用表单"
  src="/static/images/tutorial/eas/play-store-02.png"
  className="max-w-[800px]"
/>

</Step>

- 在 **控制面板** 中点击 **立即开始测试**。

<ContentSpotlight

- 要创建新版本，请前往 **控制面板**，然后点击 **创建新版本**。首先，在 **应用完整性** 下可以看到，签名密钥已由 Google Play Console 自动生成。

<Step label="4">

## 上传应用二进制文件

EAS 完成生产构建后，请按照以下步骤操作。

- 打开 EAS 控制面板，点击 **Download** 获取 **.aab** 文件。

<ContentSpotlight
  alt="下载 aab 文件"
  src="/static/images/tutorial/eas/play-store-07.png"
/>

- 返回 Google Play Console，前往 **测试和发布** > **测试** > **内部测试**。
- 在 **App Bundle** 下点击 **上传**，添加 **.aab** 文件。接着输入应用的发布信息，然后点击 **下一步**。
- 在下一个页面中点击 **保存并发布**。

<ContentSpotlight
  alt="将 aab 文件上传到 Google Play Console"
  src="/static/images/tutorial/eas/play-store-08.png"
  className="max-w-[800px]"
/>

</Step>

## 分享内部发布版本

查看 **轨道概览** 时，可以看到最新发布版本显示了临时应用名称。这是因为应用尚未经过审核。

<ContentSpotlight

  className="max-w-[800px]"

在 **发布版本** 下，可以看到应用已提供给内部测试人员。要与测试人员团队分享应用，请按照以下步骤操作。

- 切换到 **发布版本** 旁边的 **测试人员** 标签页。
- 在 **测试人员如何加入测试** 下点击 **复制链接**。可以通过电子邮件或消息发送此链接，与测试人员团队分享。

<ContentSpotlight

> **完善商店信息**：要准备应用在商店中的展示内容，请参阅[创建应用商店资源](/guides/store-assets/)，了解如何制作屏幕截图和预览。

## 添加 Google 服务账号权限密钥

> **info** **提示**：在继续执行本节中的步骤之前，请参阅[创建 Google 服务账号密钥，或从现有账号下载密钥](https://expo.fyi/creating-google-service-account)指南。

从这里开始，可以使用 [EAS Submit](/submit/android/) 自动化发布，避免手动操作。为此，需要将服务账号密钥添加到项目凭据中。

完成 Google 服务账号指南中的步骤后，将下载的 JSON 密钥上传到 EAS 控制面板。

- 在项目的 EAS 控制面板中点击 **Credentials**，然后点击 **Android** 下应用的 **Application identifier**。

<ContentSpotlight
  alt="向 EAS 控制面板添加新的 Google 服务账号密钥"
  src="/static/images/tutorial/eas/credentials-01.png"
  className="max-w-[640px]"
/>

- 在 **Service Credentials** 下点击 **Add a Google Service Account Key**。

<ContentSpotlight
  alt="在 EAS 控制面板的 Change Google Service Account Key 下上传 Google 服务账号密钥"
  src="/static/images/tutorial/eas/credentials-02.png"
  className="max-w-[640px]"
/>

- 在 **Change Google Service Account Key** 中确认已选择 **Upload new key**，然后上传下载的 JSON 密钥。这样就会将密钥添加到项目凭据中。

<ContentSpotlight
  alt="在 EAS 控制面板的 Service Credentials 下上传 Google 服务账号密钥"

<Step label="7">

## 内部发布

在 **eas.json** 中将轨道设置为 `internal`。

- 在 `submit.production` 配置文件中将 `track` 设置为 `internal`。

{/* prettier-ignore */}
```json
{
  /* @hide ... */ /* @end */
  "submit": {
    "production": {
      /* @info `track` を `internal` に設定する。 */
      "android": {
        "track": "internal"
      }
      /* @end */
    }
  }
}
```

在上面的代码片段中，我们添加了 [`track`](/eas/json/#track) 属性，并将其值设置为 `internal`。这样就可以通过 `eas submit` 命令上传生产构建，并将其发布到 Google Play 商店的内部测试频道。

- 现在运行 `eas submit` 命令，发布新的内部测试版本。

<Terminal cmd={['$ eas submit --platform android']} />

- 此命令会在 Google Play Console 中自动创建新的内部发布版本。

<ContentSpotlight
  alt="由 EAS Submit 在 Google Play Console 中自动创建的内部发布版本"
  src="/static/images/tutorial/eas/play-store-18.png"
  className="max-w-[800px]"
/>

</Step>

<Step label="8">

## 生产发布

要将应用发布到生产环境，请按照以下步骤操作。

- 将 **eas.json** 中 `track` 的值改为 `production`。

```json
{
  /* @hide ... */ /* @end */
  "submit": {
    "production": {
      "android": {
        /* @info トラックを `production` に変更する。 */
        "track": "production"
        /* @end */
      }
    }
  }
}
```

- 可以重新使用内部测试发布版本中使用的同一个 EAS Build。运行 `eas submit` 命令，将其发布到 Play 商店。

<Terminal cmd={['$ eas submit --platform android']} />

- 要创建轨道并将应用提交给 Google Play 商店审核，请前往 **测试和发布** > **正式版**，然后在 **发布版本** 下选择要提交审核的构建。

</Step>

<Step label="9">

## 自动发布

对于今后的发布，可以在 `eas build` 中添加 [`--auto-submit`](/build/automate-submissions/) 标志，将创建构建和提交到 Play 商店合并为一个步骤，从而提高效率。

<Terminal cmd={['$ eas build --platform android --auto-submit']} />

</Step>
