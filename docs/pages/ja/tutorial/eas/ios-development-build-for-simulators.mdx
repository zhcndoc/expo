本章将使用 EAS Build 创建一个可在 iOS Simulator 上运行的开发构建版本。

面向 iOS Simulator 的开发构建版本将以 **.app** 格式生成，这与面向 iOS 真机的版本不同。

## 在 eas.json 中创建用于模拟器的构建配置文件

在 **eas.json** 中添加一个名为 `ios-simulator` 的新构建配置文件，并将 [`ios.simulator`](/eas/json/#simulator) 属性设置为 `true`。

{/* prettier-ignore */}
```json eas.json
{
  "build": {
    "development": {
      /* @hide ... */ /* @end */
    },
    /* @info `simulator` プロパティは iOS Simulator ビルドに必須です。 */
    "ios-simulator": {
      "ios": {
        "simulator": true
      }
    }
    /* @end */
  }
}
```

开发构建需要在配置文件中定义 `developmentClient` 和 `distribution` 属性。为了避免重复，让我们继承 `development` 配置文件的属性。

```json eas.json
{
  "ios-simulator": {
    /* @info `extends` キーワードは `development` プロファイルのプロパティを継承します。 */
    "extends": "development",
    /* @end */
    "ios": {
      "simulator": true
    }
  }
}
```

## 面向 iOS Simulator 的开发构建

<Step label="1">

### 创建

运行 `eas build` 命令，并将平台指定为 `ios`，将构建配置文件指定为 `ios-simulator`。

<Terminal cmd={['$ eas build --platform ios --profile ios-simulator']} />

首次创建构建时，此命令会显示以下问题。

- **What would you like your iOS bundle identifier to be?**（您希望使用什么 iOS bundle identifier？）按 <kbd>Return</kbd>，选择显示的默认值。这会将 [`ios.bundleIdentifier`](/versions/latest/config/app/#bundleidentifier) 添加到 **app.json** 中。
- **iOS app only uses standard/exempt encryption?**（此 iOS 应用是否仅使用标准加密或豁免加密？）按 <kbd>Y</kbd>，选择默认值。由于此应用不使用加密，**Info.plist** 文件中的 `ITSAppUsesNonExemptEncryption` 会被设置为 `NO`，从而处理发布到 TestFlight 或 Apple App Store 时的合规性检查。如果您在发布自己的应用时使用了加密，请选择 `N`，这样从下次开始就可以跳过此问题。

回答问题后，EAS Build 会进入队列，EAS CLI 会显示一个链接，您可以通过该链接在 EAS 控制面板中查看构建的详细信息和进度。

<ContentSpotlight
  alt="iOS Simulator 构建详细信息页面"

/>

<Collapsible summary="构建详细信息页面包含哪些内容？">

构建详细信息页面会显示构建类型、配置文件、Expo SDK 版本、应用版本、构建编号、最后一次提交的哈希值，以及启动构建的开发者或账户所有者。

在上图中，**Build artifact** 的当前状态表示构建正在进行。完成后，您可以从此部分下载构建。**Logs** 中会列出 iOS 在 EAS Build 上的构建过程的各个步骤。为简洁起见，这里不介绍每个步骤的详细信息。详情请参阅 [iOS 构建过程](/build-reference/ios-builds/)。

</Collapsible>

<Collapsible summary="什么是 iOS bundle identifier？">

`ios.bundleIdentifier` 是应用的唯一名称。如果您现在发布应用，Apple App Store 会使用此属性的值来识别商店中的应用。

此表示法以 `host.owner.app-name` 的形式定义。例如，在示例应用中，它是 `com.owner.stickersmash`，其中 `com.owner` 是域名，`stickersmash` 是应用名称。

</Collapsible>

</Step>

<Step label="2">

### 安装

构建完成后，EAS CLI 会在终端中询问您是否要在 iOS Simulator 上运行构建。按 <kbd>Y</kbd>。

<ContentSpotlight
  alt="EAS CLI 自动提供在 iOS Simulator 上运行构建的选项"
  src="/static/images/tutorial/eas/ios-sim-cli.png"
  className="max-w-[480px]"
/>

<Collapsible summary="另一种方法：使用 Expo Orbit">

您也可以使用 [Expo Orbit](https://expo.dev/orbit) 安装开发构建。在 EAS 控制面板的 **Build artifact** 中点击 **Open with Expo Orbit**，开发构建就会安装到 iOS Simulator 上。

</Collapsible>

</Step>

<Step label="3">

### 运行

在项目目录中运行 `npx expo start` 命令，启动开发服务器。

<Terminal
  cmd={{
    npm: ['$ npx expo start'],
    yarn: ['$ yarn expo start'],
    pnpm: ['$ pnpm expo start'],
    bun: ['$ bun expo start'],
  }}
/>

在终端窗口中按 <kbd>I</kbd>，即可在 iOS Simulator 中打开项目。

</Step>
