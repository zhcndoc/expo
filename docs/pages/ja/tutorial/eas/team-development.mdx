OTA（Over-The-Air）更新通常用于在应用商店版本发布之间，分发小型错误修复和小型变更。你可以更新示例应用中非原生的部分，例如 JavaScript 代码、样式和图像。

本章将使用 [EAS Update](/eas-update/introduction/) 与团队共享变更。这样，你就可以[快速与自己和团队共享预览](/review/overview/)。

<Step label="1">

## 安装 expo-updates 库

要初始化项目并分发更新，需要 [`expo-updates`](/versions/latest/sdk/updates/) 库。使用以下命令安装。

<Terminal
  cmd={{
    npm: ['$ npx expo install expo-updates'],
    yarn: ['$ yarn expo install expo-updates'],
    pnpm: ['$ pnpm expo install expo-updates'],
    bun: ['$ bun expo install expo-updates'],
  }}
/>

</Step>

<Step label="2">

## 配置 EAS Update

按照以下步骤使用 EAS Update 初始化项目。

- 由于应用配置使用动态的 **app.config.js**，因此需要添加 [`updates`](/versions/latest/config/app/#updates) 和 [`runtimeVersion`](/eas-update/runtime-versions/#setting-runtimeversion) 属性，才能让项目支持 EAS Update。运行以下命令，从 EAS 获取这些属性和值，然后手动将其复制到 **app.config.js** 中。

<Terminal cmd={['$ eas update:configure']} />

<Collapsible summary="如果项目使用 app.json（非动态配置），该怎么办？">

如果项目没有使用动态 app config（而是使用 **app.json**，不是 **app.config.js**），上面的命令会让应用支持 EAS Update，并将适当的属性添加到 **app.json** 和 **eas.json** 中。

</Collapsible>

- 为了继续设置，再次运行 `eas update:configure`。此时，**eas.json** 中的所有构建配置都应该添加了 [`channel`](/eas/json/#channel)。

{/* prettier-ignore */}
```json eas.json
{
  "build": {
    "development": {
      /* @hide ... */ /* @end */
      /* @info */
      "channel": "development"
      /* @end */
    },
    "ios-simulator": {
      /* @hide ... */ /* @end */
    },
    "preview": {
      /* @hide ... */ /* @end */
      /* @info */
      "channel": "preview"
      /* @end */
    },
    "production": {
      /* @hide ... */ /* @end */
      /* @info */
      "channel": "production"
      /* @end */
    }
  }
  /* @hide ... */ /* @end */
}
```

> **info** `eas update:configure` 命令会将 `channel` 添加到 **eas.json** 中的所有构建配置。不过，由于 `ios-simulator` 配置继承自 `development` 配置，因此没有必要为其设置其他 `channel`。可以安全地从上面的配置中删除 `ios-simulator.channel`。

<Collapsible summary="什么是 channel？">

[通道](/eas-update/how-it-works/#conceptual-overview)用于将构建分组。如果 Android 和 iOS 的构建都在应用商店中，可以为它们都设置 production 通道。之后，只要让 EAS Update 面向 production 通道，所有具有 production 通道的构建都会收到更新。

</Collapsible>

</Step>

<Step label="3">

## 创建开发构建

由于最近的构建中不包含 `expo-updates` 库，因此需要创建新的开发构建。运行以下命令。

<Terminal cmd={['$ eas build --platform android --profile development']} />

> 这里使用面向 Android 真机的开发构建来演示更新的运行方式。使用 `--platform all` 或 `--platform ios`，可以创建面向两个平台的构建，或仅面向 iOS 的构建。

创建新的开发构建后，请务必将其安装到设备上。

</Step>

<Step label="4">

## 修改应用的 JavaScript 代码

尝试修改示例应用的 JavaScript 代码。如果没有使用 [Sticker Smash 应用](/ja/tutorial/eas/introduction/#prerequisites)，可以修改自己代码中的任意部分，并在应用中查看变化。

这里，我们将示例应用中第一个按钮的文本从 **Choose a photo** 修改为 **Select a photo**。

```tsx app/(tabs)/index.tsx
<Button theme="primary" label="Select a photo" onPress={pickImageAsync} />
```

</Step>

<Step label="5">

## 发布更新

不要为了让团队测试此变更而创建新的构建，而是发布更新。

<Terminal cmd={['$ eas update --channel development --message "Change first button label"']} />

上面的命令使用了 `development` 通道。所有更新都与[通道名称](/eas-update/how-it-works/#publishing-an-update)关联。这类似于 git 提交始终与 git 分支关联。

也就是说，通过在构建配置中使用 `development` 通道，然后发布更新，你是在请求 EAS 将此更新发送到具有 `development` 通道的构建。创建 EAS Update 通道后，它会自动映射到同名的分支。

更新发布后，CLI 会显示相关信息。

<ContentSpotlight
  alt="EAS Update 已通过 CLI 提示成功发布"
  src="/static/images/tutorial/eas/update-01.png"
/>

点击 **Website link**，即可在 EAS 控制面板的 **Over-the-air updates** > **Update groups** 中查看更新。

<ContentSpotlight
  alt="EAS 控制面板显示了开发构建最近发布的更新"
  src="/static/images/tutorial/eas/update-02.png"
  className="max-w-[800px]"
/>

</Step>

<Step label="6">

## 在开发构建中即时预览更新

要在开发构建中即时预览更新，请按以下步骤操作。

- 在开发构建中登录 Expo 账户。
- 打开 **Extensions** 选项卡。
- 在 **EAS Update** 下找到 **Branch: development**。
- 点击 **Open** 打开更新。

</Step>

<Step label="7">

## 与 Preview 和 production 构建共享变更

开发构建以外的更新（Preview 或 production）会在应用启动时请求新的更新，并自动将其下载到设备。

使用 Preview 或 production 构建的团队成员会收到发送到相应分支的变更作为更新。

例如，面向 `preview` 构建时，运行以下命令。

<Terminal cmd={['$ eas update --channel preview --message "Change first button label"']} />

下面是面向 `preview` 构建发布更新的示例。要测试更新，请强制退出应用，然后重新打开两次，变更就会下载并显示。

</Step>
