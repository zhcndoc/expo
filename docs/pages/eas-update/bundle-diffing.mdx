启用 bundle 差分后，EAS Update 会在可能的情况下提供 **bundle 补丁**。当你发布新更新时，EAS Update 可以生成一个较小的文件，其中仅包含设备上当前运行的 bundle 与新 bundle 之间的差异。这通常可以显著减少更新下载大小。

<Prerequisites>
  <Requirement title="Expo SDK 55 或更高版本">你的应用必须使用 Expo SDK 55 或更高版本。</Requirement>
</Prerequisites>

## 启用 bundle 差分

Bundle 差分在两种情况下可用。已经运行已发布更新的设备在有更新版本可用时会获取补丁。新安装设备在首次检查更新时也可以获取补丁，而不是下载完整的新 bundle，前提是构建中的内嵌 bundle 已上传。第一种方式在 SDK 56 及更高版本中默认启用，第二种方式在 SDK 58 及更高版本中默认启用。

### 更新之间的补丁

在 SDK 56 及更高版本中默认启用。在 SDK 55 中，请在项目的 [应用配置](/workflow/configuration/) 中将 `updates.enableBsdiffPatchSupport` 设置为 `true` 以启用。

```json app.json
{
  "expo": {
    "updates": {
      "enableBsdiffPatchSupport": true
    }
  }
}
```

要在 SDK 56 及更高版本中禁用，请将 `enableBsdiffPatchSupport` 设置为 `false`。

### 来自内嵌 bundle 的补丁

<Tabs>

<Tab label="SDK 58 及更高版本">

EAS Build 会在构建完成后上传内嵌 bundle。之后发布到同一频道的更新就可以作为相对于它的补丁来提供。无需进行配置。

要禁用上传，请在 **eas.json** 的构建配置中，将 `env` 下的 `EAS_UPDATE_UPLOAD_EMBEDDED_BUNDLE` 环境变量设置为 `0`：

```json eas.json
{
  "build": {
    "production": {
      "env": {
        "EAS_UPDATE_UPLOAD_EMBEDDED_BUNDLE": "0"
      }
    }
  }
}
```

</Tab>

<Tab label="SDK 57 及更低版本">

> **信息** 在 SDK 57 及更低版本中，此模式为[实验性](/more/release-statuses/#experimental)功能，需要选择启用。标志及其行为可能会发生变化。

要启用，请在 **eas.json** 的构建配置中，将 `EAS_UPDATE_EXPERIMENTAL_UPLOAD_EMBEDDED_BUNDLE` 环境变量设置在 `env` 下：

```json eas.json
{
  "build": {
    "production": {
      "env": {
        "EAS_UPDATE_EXPERIMENTAL_UPLOAD_EMBEDDED_BUNDLE": "1"
      }
    }
  }
}
```

构建完成后，EAS Build 会上传内嵌 bundle。随后发布到同一频道的更新就可以作为相对于它的补丁来提供。

</Tab>

</Tabs>

[使用 [`eas/build`](/custom-builds/schema/#easbuild) 的[自定义构建](/custom-builds/get-started/)会以相同方式上传内嵌 bundle。如果你的自定义构建配置使用单独的步骤，请添加 [`eas/upload_embedded_bundle`](/custom-builds/schema/#easupload_embedded_bundle) 步骤。

只有在项目中配置了 EAS Update 且构建配置设置了 `channel` 时，EAS Build 才会上传 bundle。对于开发构建和 iOS 模拟器构建，它会跳过上传。要确认上传是否完成，请使用 [`eas update:embedded:list`](#manage-uploaded-embedded-bundles) 查找 bundle。

如果你不使用 EAS Build，也可以自行上传内嵌 bundle。将 `--bundle` 指向 JavaScript bundle，将 `--manifest` 指向原生构建生成的 **app.manifest**：

<Terminal
  cmd={[
    '$ eas update:embedded:upload --platform [platform] --bundle [path] --manifest [path] --channel [name]',
  ]}
/>

## 管理已上传的嵌入式包

使用 `eas update:embedded:list` 查找 ID，然后将它们传递给查看或删除命令。

列出为你的项目注册的嵌入式包：

<Terminal cmd={['$ eas update:embedded:list']} />

查看单个嵌入式包：

<Terminal cmd={['$ eas update:embedded:view [id]']} />

删除一个嵌入式包：

<Terminal cmd={['$ eas update:embedded:delete [id]']} />

该命令可以安全重试。

## 验证 bundle diff 是否正在被提供

### Expo 网站

你可以在 [更新详情](https://expo.dev/accounts/[account]/projects/[project]/updates) 页面上确认是否正在提供 bundle diff。打开你发布的 Update Group，然后选择你想检查的平台。

<ContentSpotlight
  alt="Bundle diffing 下载"
  src="/static/images/eas-update/bundle-diffing.png"
/>

### Updates API

你可以通过使用 `Updates.readLogEntriesAsync()` 检查更新日志来确认是否正在提供 bundle diff。如果你的应用收到了补丁，你会看到一条表示补丁已成功应用的记录（例如，“patch successfully applied”）。

## 补丁生成与分发

EAS Update 使用 [bsdiff 算法](https://en.wikipedia.org/wiki/Bsdiff) 来生成 bundle 补丁。

只有在以下情况下才会提供补丁：

- **它明显小于完整 bundle。** 如果不是，EAS Update 会改为提供完整 bundle。
- **它可以高效计算。** 如果生成补丁消耗的资源过多，EAS Update 会改为提供完整 bundle。

## 当前限制

- **新安装设备在首次更新时会接收完整 bundle，除非构建中的内嵌 bundle 已上传。** SDK 58 及更高版本默认采用此方式。请参阅[来自内嵌 bundle 的补丁](#patches-from-the-embedded-bundle)。
- **并非每一种可能的更新配对都会立即保证提供补丁。** 当发布一个更新时，EAS Update 只会预先针对该 channel 上第二新的更新计算一个补丁。如果设备在运行另一个已发布的更新时请求新更新，起初将收到完整 bundle。随后会按需为该特定基础更新生成补丁，并提供给未来类似的请求。
- **补丁会在发布后不久生成。** 从发布一个更新到补丁就绪之间，可能需要几分钟。在这段时间内，设备可能会收到完整 bundle。
