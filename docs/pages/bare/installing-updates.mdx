`expo-updates` 是一个库，可让你的应用管理应用代码的远程更新。它会与已配置的远程更新服务通信，以获取可用更新的信息。本指南说明如何为现有的 React Native 项目进行配置，以便与 [EAS Update](/eas-update/introduction) 一起使用。EAS Update 是一项托管的远程更新服务，包含用于简化 `expo-updates` 库安装和配置的工具。

<Collapsible summary="你在项目中使用 Continuous Native Generation（CNG）吗？">

你可能正在查看错误的指南。要在使用 [CNG](/workflow/continuous-native-generation/) 的项目中使用 `expo-updates`，请参阅 [EAS Update“开始使用”](/eas-update/getting-started/)。

</Collapsible>

  <Requirement title="安装并配置 expo 包">

  </Requirement>
</Prerequisites>

## 安装

开始之前，先安装 `expo-updates`：

<Terminal
  cmd={{
    npm: ['$ npx expo install expo-updates'],
    yarn: ['$ yarn expo install expo-updates'],
    pnpm: ['$ pnpm expo install expo-updates'],
    bun: ['$ bun expo install expo-updates'],
  }}
/>

然后，安装 iOS 的 pods：

<Terminal
  cmd={{
    npm: ['$ npx pod-install'],
    yarn: ['$ yarn dlx pod-install'],
    pnpm: ['$ pnpm dlx pod-install'],
    bun: ['$ bunx pod-install'],
  }}
/>

## 配置 expo-updates 库

按照以下各节中的 diff 进行相应更改，以便在项目中配置 `expo-updates`。

### JavaScript 和 JSON

运行 `eas update:configure`，在 **app.json** 中设置 `updates` URL 和 `projectId`。

<Terminal cmd={['$ eas update:configure']} />

修改 **app.json** 的 `expo` 部分。如果你是使用 `npx @react-native-community/cli@latest init` 创建的项目，则需要添加以下更改，包括 [`updates` URL](/versions/latest/config/app/#url)。

> 下方示例中的 `updates` URL 和 `projectId` 适用于 EAS Update。运行 `eas update:configure` 时，EAS CLI 会为 EAS Update 服务正确设置此 URL。

<DiffBlock source="/static/diffs/expo-updates-app-json.diff" />

如果你想改为设置一个[自定义 `expo-updates` 服务器](https://github.com/expo/custom-expo-updates-server)，请在 **app.json** 中将你的 URL 添加到 `updates.url`。

--- a/app.json
+++ b/app.json

### iOS

将文件 **Podfile.properties.json** 添加到 **ios** 目录：

```json ios/Podfile.properties.json
{
  "expo.jsEngine": "hermes"
}
```

修改 **ios/Podfile**，以检查 Expo 文件中的 JS 引擎配置（JSC 或 Hermes）：

<DiffBlock source="/static/diffs/expo-updates-ios-podfile.diff" />

使用 Xcode，将 **Expo.plist** 文件添加到 **ios/your-project/Supporting**，内容如下，以与 **app.json** 的内容保持一致：

```xml Expo.plist
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN" "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
<plist version="1.0">
  <dict>
    <key>EXUpdatesCheckOnLaunch</key>
    <string>ALWAYS</string>
    <key>EXUpdatesEnabled</key>
    <true/>
    <key>EXUpdatesLaunchWaitMs</key>
    <integer>0</integer>
    <key>EXUpdatesRuntimeVersion</key>
    <string>1.0.0</string>
    <key>EXUpdatesURL</key>
    <string>http://localhost:3000/api/manifest</string>
  </dict>
</plist>
```

## 在构建时配置更新通道

构建中的 `channel` 属性允许你将更新指向特定类型的构建。例如，它允许你向预览版构建发布更新，而不影响生产环境部署。

此属性最终也会设置在上文修改的 **AndroidManifest.xml** 和 **Expo.plist** 文件中。通常会在构建前设置，以便在生产构建和非生产构建之间切换。如果你使用 EAS Build 构建项目，`channel` 会在 **eas.json** 构建配置文件中设置。然后，EAS Build 会在原生构建步骤开始前将其应用到这些文件中。

如果你在本地或使用其他服务构建，则需要自行在这些文件中设置通道：

### Android

在 **android/app/src/main/AndroidManifest.xml** 中，在 `<application>` 元素内添加请求标头 `meta-data` 条目：

```xml android/app/src/main/AndroidManifest.xml
<meta-data android:name="expo.modules.updates.UPDATES_CONFIGURATION_REQUEST_HEADERS_KEY" android:value="{&quot;expo-channel-name&quot;:&quot;your-channel-name&quot;}"/>
```

### iOS

在 **Expo.plist** 中，在现有的 `<dict>` 元素内添加 `EXUpdatesRequestHeaders` 字典：

```xml ios/project-name/Supporting/Expo.plist
<key>EXUpdatesRequestHeaders</key>
<dict>
  <key>expo-channel-name</key>
  <string>your-channel-name</string>
</dict>
```

> **info** 如果你之后采用 CNG，也可以改为在 **app.json** 中通过 [`updates.requestHeaders`](/versions/latest/config/app/#requestheaders) 配置通道。随后，在你的流水线中运行 `npx expo prebuild`，即可将通道写入这些文件。请参阅[在 app.json 中配置更新通道](/eas-update/getting-started/#configure-update-channels-in-appjson)。
