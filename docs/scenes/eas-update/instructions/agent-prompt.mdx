```text wrap
在我的 Expo 项目中设置 EAS Update，这样我无需创建新构建即可发布 JavaScript 和资源更改。按顺序完成以下步骤。

1. 确认项目类型。如果 android 和 ios 目录没有提交到版本控制中，则项目使用 CNG。如果已提交，则这是一个裸 React Native 项目，标记为“仅裸项目”的步骤也适用。
2. 使用 `npm install -g eas-cli` 安装或升级 EAS CLI。
3. 使用 `eas whoami` 检查我是否已登录。如果没有，请运行 `eas login`。
4. 仅裸项目：准备原生项目。
   - 如果项目没有 Expo 模块，请运行 `npx install-expo-modules@latest`，使其使用 Expo CLI 和 Metro 配置。
   - 如果缺少此程序包，请运行 `npx expo install expo-updates`，然后运行 `npx pod-install`。
   - 如果 index.js 调用了 `AppRegistry.registerComponent(appName, () => App)`，请从 `expo` 导入 `registerRootComponent`，并将该调用替换为 `export default registerRootComponent(App)`。然后在 `MainActivity` 和 `AppDelegate` 中将模块名称设为 "main"，而不是应用名称。
5. 运行 `eas update:configure`。它会将 `runtimeVersion` 和 `updates.url` 写入应用配置，并在缺少 `extra.eas.projectId` 时添加该项。
6. 仅裸项目：检查 `eas update:configure` 修改的原生文件。AndroidManifest.xml 需要包含 `expo.modules.updates.EXPO_UPDATE_URL` 和 `EXPO_RUNTIME_VERSION` 元数据，strings.xml 需要包含 `expo_runtime_version` 字符串，ios/<project>/Supporting/Expo.plist 需要包含 `EXUpdatesURL` 和 `EXUpdatesRuntimeVersion`。如果使用 Xcode 构建项目，请将 Expo.plist 添加到 Xcode 项目中。
7. 设置更新渠道：
   - 使用 EAS Build：在 eas.json 的 `preview` 和 `production` 配置文件中设置 `channel`，或在此项目使用的配置文件中设置。
   - 不使用 EAS Build，CNG：在应用配置中将 `updates.requestHeaders` 设为 `{"expo-channel-name": "<channel>"}`。此设置将在下一次运行 `npx expo prebuild` 时生效。
   - 不使用 EAS Build，裸项目：将 `expo.modules.updates.UPDATES_CONFIGURATION_REQUEST_HEADERS_KEY` 元数据（值为 `{"expo-channel-name":"<channel>"}`）添加到 AndroidManifest.xml，并在 Expo.plist 中添加 `EXUpdatesRequestHeaders` 字典，将 `expo-channel-name` 设为该渠道。
8. 停下并询问我：“所有内容都已配置完成。你是否有设备或模拟器上的预览构建？”如果我说没有，请在运行 `eas build --profile preview --platform <platform>` 前征求我的同意，平台使用我指定的平台。
9. 停下并询问我：“所有内容都已设置完成。你现在要发布更新吗？”如果我说要，请询问渠道、消息和环境，然后运行 `eas update --channel <channel> --message "<message>" --environment <environment>`。
10. 告诉我如何测试更新：从开发构建的 Extensions 选项卡加载更新，或强制关闭并重新打开发布构建两次。

使用此项目已有的包管理器，并报告你运行了哪些命令。

有关 EAS Update 入门指南，请参阅 https://docs.expo.dev/eas-update/getting-started/。
```
